Der Lebenszyklus einer Code-Änderung (CI/CD Flow)
Jedes Mal, wenn du Code änderst, läuft die Struktur wie folgt ab:

 1-Continuous Integration (Jenkins):
    1- Code & Build: Jenkins holt den Code aus java-app/, 
    Maven baut die .jar-Datei und JUnit testet sie.
    2- Quality Gate: Der Code wird an den SonarQube-Container geschickt. 
    Schlägt der Qualitätscheck fehl, bricht die Pipeline ab.
    3- Containerisierung: Jenkins nutzt den Docker-Socket des Ubuntu-Hosts, 
    baut ein neues Docker-Image (java-app:1.0.X) und taggt es.
 
 2- Continuous Deployment (Helm & Argo CD):
  1- Test-Phase: Jenkins nutzt Helm, um das Image direkt in das k3d-Cluster (Namespace test) einzuspielen. Selenium/UAT-Tests prüfen die laufende App.
  2- GitOps Promotion: Jenkins editiert die values.yaml im Ordner charts/ und trägt das neue Image-Tag ein.
  3- Production: Argo CD bemerkt die Änderung in der values.yaml sofort,
  zieht das neue Image und rollt es ohne Downtime im Namespace prod aus.
